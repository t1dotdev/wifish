# AGENTS.md

`wifish` — local single-screen WPA/WPA2 handshake-cracking console. Next.js 15 + React 19, TypeScript (strict). No lint/format tooling. See `PRODUCT.md` for product constraints, exact terminology, and voice — read it before changing UI copy.

## Commands

- `npm run dev` — dev server on port **3200** (non-default, pinned via `-p 3200` in both `dev` and `start`).
- `npm test` — `node --test tests/*.test.ts`. Plain `node:test` on Node's native type stripping (no tsx/ts-node), no server needed. Single file: `node --test tests/sessions.test.ts`.
- `npm run build` / `npm start` — production (port 3200). **Build is also the typecheck** (tsc runs inside `next build`); bare `tsc --noEmit` fails before the first build because `next-env.d.ts` is generated by dev/build.
- Dev builds go to `.next-dev/`, production to `.next/` (see `next.config.mjs`) — deliberate, so `npm run build` never clobbers a running dev server. Don't "fix" this.
- Both `bun.lock` and `package-lock.json` exist; no `packageManager` field. Don't delete either; after changing deps run `npm install` then `bun install` to keep both in sync.
- `typescript` is pinned to **^6** — Next 15.5 rejects TS 7's native compiler. Don't bump past 6 without upgrading Next.

## TypeScript conventions

- Path alias `@/*` maps to the repo **root** — set in `tsconfig.json` `paths` *and* as an explicit webpack alias in `next.config.mjs` (TS ≥6 removed `baseUrl`, which Next 15's tsconfig-paths support relied on — keep both).
- App code imports lib extensionless via the alias (`@/lib/fs`); **lib-internal and test imports use explicit `.ts` extensions** (`./sessions.ts`, `../lib/sessions.ts`) because Node's type stripping resolves files exactly. `allowImportingTsExtensions: true` exists for this — don't remove it.
- Erasable-syntax-only TS (no enums, namespaces, or parameter properties) — tests and `lib/` run directly under Node.

## Runtime prerequisites

Routes shell out to `hcxpcapngtool` (convert), `hashcat` and/or `aircrack-ng` (crack). Not bundled — missing binaries surface as 500 "not installed". Tests never need them.

## Layout

- `app/page.tsx` — the entire UI (one client component, incl. hashcat/aircrack log parsing).
- `app/api/{files,file,convert,crack,cracked}/route.ts` — the entire backend.
- `lib/` — all domain logic; the only thing tests import:
  - `fs.ts` — data dirs + path safety
  - `sessions.ts` — session/process store
  - `session-stream.ts` — SSE over the saved log
- `crack.sh` — legacy standalone CLI predecessor using top-level `pcap/` etc. Not part of the app; don't wire it in.

## Invariants (easy to break)

- Operator data lives in `.wifish/{pcap,hc22000,wordlists,cracked,sessions}` resolved from `process.cwd()` (gitignored) — `next` must run from the repo root. `hashcat.potfile` is also pinned to the repo root via `--potfile-path`, not `~/.hashcat`.
- The crack session store is a singleton on `globalThis.__wifishSessions` (declared in `lib/sessions.ts`) so it survives Next dev hot-reloads — preserve that pattern in `app/api/crack/route.ts`.
- Crack children spawn `detached` with stdout/stderr writing directly to the session log file fd, so server reloads and browser disconnects can't kill the run or close its pipe. The SSE stream only *watches the log file* and must never signal the child; `DELETE /api/crack` is the only stop path.
- One panel-started crack at a time (409 on concurrent start) — intentional product constraint, not a limitation to remove.
- All file access goes through `safeFile()` (`lib/fs.ts`), whose `path.basename` call is the traversal guard. Never bypass it with raw user-supplied paths.
- Tests inject `spawnProcess`/`discover` and use temp dirs — keep them hermetic; never touch the real `.wifish/` or spawn real hashcat/aircrack. The route test rewrites `route.ts` source to a temp file and imports that (Node strips types on disk, not in `data:` URLs).
